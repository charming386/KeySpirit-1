| 项目 | 内容 |

## 一、概述

本版本修一个缺陷：**商店的「max」不是真的 max**；同时把此前只在本地跑过的数值重做正式入库（详见第三节）。

「单次数量」切到 `max` 时，本意是「把身上的金币全花光，能买多少买多少」。但实现里数量是 `int`，并且在 10 亿（1B）处硬性封顶。于是金币一旦上到千亿量级，max 就退化成「一次只买 1B」——面板上明明写着 max，行的右侧却始终是 `×1B`，想真买完得连点七八下。开墨匣同理（单价 250，187.2B 金币本来能开 749M 个，也被压在 1B 以内）。

## 二、本版本修复

| 问题 | 说明 |
| --- | --- |
| `max` 档被 `int` 封顶在 10 亿 | max 的数量改由金币实际余额算出（`Big` 运算，不再转 `int`）：187.2B 金币 / 25 = **7.5B 颗墨晶**，一次点完、金币清零。买墨晶与开墨匣的数量参数都改成 `Big`，跟着金币走到 1.8e+303 量级 |
| max 档显示的数字不是真实数量 | max 时行内数量显示算出来的实际值（`×7.5B`），不再一律 `×1B`；固定档位仍是 `1 / 10 / 100 / 1K / 1M / 1B` |
| 超大数量开匣的计数溢出 | max 档一次能开 1e+97 个匣，逐档命中数改用 `double` 计（原来 `long` 会溢出），总结算量用 `Big`；「开匣次数」统计超上限时饱和而不是变负。≥2001 个仍走正态近似，耗时恒定 |
| 「补到够升墨刃」在 300 级以上算错（同一处根因） | 差额同样按 `int` 返回，墨刃升到 300 级（单级成本超 21 亿）后溢出成负数，界面显示「已够」但实际差一大截，且点不动。差额改按 `Big` 返回，按差额补货也按 `Big` 结算 |

## 三、随本版一并发布的数值与系统改动

这一批改动在 v0.12.1 之后完成，此前只在本地预发布包上跑过；GitHub 上的包以本版为准。

| 改动 | 内容 |
| --- | --- |
| 升级经验重做 | 由「40 × 等级^1.35」改为「本轮最高层单只经验 × (2 + 0.58 × √层数)」。需求挂在**本轮最高层**上，所以退回低层刷不会刷级；第 1 层约两只小怪升一级，300 层要打一层，3000 层要两三层——越往上越慢 |
| 强化成本上调 | 墨晶单级成本由 ×1.062 提到 ×1.07。怪每上一层强 6%、成本涨 7%，这才是「该转生了」这件事真正成立的原因 |
| 等级不再只是荣誉 | 每级基础攻 +1 / 生命 +10 / 防御 +0.5，叠在原有的 +1.5% 线性乘区之上；角色页新增「每级」「距下一级（约 N 只同层小怪）」，攻 / 血 / 防三行标注本体值 |
| 金币袋减半 | 袋值由「单只金币 × 5」改为「单只金币 × 2.5」，同样吃等级乘区 |
| 转生改为「没收现金、保留投入」 | 金币 / 墨晶 / 待领金币袋清零，四件本命器强化等级与墨根保留，日志记一行「清零金币 X / 墨晶 Y」。界线是能不能带走——喂进本命器的墨晶已经是永久等级，躺账上的钱不是 |
| 每日礼包必须手动领 | 撤掉「领取」页底部的「一键全领」，两档礼包（5,000 / 20,000）只能点各自的档位行领取；金币袋仍是一行点一次全部入袋 |
| 初始化重置 | 设置 › 危险操作 › 初始化重置：暗红字，悬停 0.4 秒出解释，点击底纹变黄、再变橙，第三下才把存档恢复成刚下载的样子（进度 / 货币 / 统计 / 设置全部清零，日志保留） |

## 四、兼容性

存档结构未改动（`ShopBatch` 等字段与 v0.12.1 一致），可直接覆盖安装，无需迁移，已买的墨晶、已开的匣、强化等级、墨根全部保留。

需要注意的两点：

- **从 GitHub 上的 v0.12.1 升上来的存档，升级速度会明显变慢**。按新曲线，升一级约等于「打一两层」，不再是「打一只怪升一级多」。老存档已有的等级不压缩、原样保留——它同时意味着新曲线下的等级乘区比应得值高一些，属于版本切换的一次性红利。
- **墨晶不足时的直觉会变**：单级强化成本改为 ×1.07 后，同一层能升的级数变少，「补到够升墨刃」会点得比之前勤。

## 五、说明

本版本的修复由 AI 编写代码，人工负责缺陷复现、规则确认与回归验证。项目内置 **102 项**自测断言（上一版 100 项，本版新增 2 条：max 档按金币算出 40B 而不是 10 亿、金币到 1e100 时 max 开匣不退回 1B 且计数不溢出），覆盖大数显示、数值封顶、怪物曲线与物种表、战斗结算、金币袋、商店、墨匣、强化连升、层数跳转、转生、每日敲击与礼包、初始化重置、存档与面板状态。

> 转生代价（墨渊税）已随「转生没收现金」作废，策划稿 6.7 节保留为历史提案。
