## 一、1 位小数把「涨了多少」抹掉了

1e15 以上的数字走科学记数法，原来只留 **1 位小数**：

```
9.94e+15  →  显示 9.9e+15
9.99e+15  →  显示 9.9e+15     ← 两者看着一模一样
9.999e+15 →  显示 9.9e+15
```

而墨衣每升一级只涨 **6%**，一条命/攻击/防御在 620 层这个量级上，连点十几级墨衣，面板上的数字**一动不动**：

| 墨衣等级 | 实际生命 | 旧显示 | 新显示 |
|---|---|---|---|
| 550 | 9.940e+15 | 9.9e+15 | **9.940e+15** |
| 551 | 1.054e+16 | 10.5e+15 | **1.053e+16** |
| 552 | 1.117e+16 | 11.1e+15 | **1.116e+16** |

第一级因为刚好跨过 1e16，指数变了还能看出来；之后连续几十级都会挤在 `1.0e+16` 附近。玩家会以为强化没生效。

## 二、改动

```csharp
public const int SciDigits = 3;                 // 原为 1（写死在各分支里）

static string Sci(double mantissa, int exp)     // ≥1e300 与 ≥1e15 两处共用
{
    int e = exp;
    double scale = Math.Pow(10, SciDigits);
    double m = Math.Floor(mantissa * scale) / scale;
    if (m < 1) { e -= 1; m = Math.Floor(mantissa * scale * 10) / scale; }
    return m.ToString("0." + new string('0', SciDigits)) + "e+" + e;
}
```

三条性质都保留了：

| 性质 | 说明 |
|---|---|
| **向下取整**（不四舍五入） | 显示值永远不超过真实值，不会出现「看着够但买不起」 |
| **K/M/B/T 段仍是 1 位小数** | 那是带单位后缀的短写法，不是科学记数法；`842.7K`、`213.0T` 不动 |
| **固定宽度** | 尾数 `.000` 也保留（`1.000e+15`），菜单文字不会左右跳 |

## 四、顺手修掉一处被挤爆的行

商店「补到够升墨刃」这一行原本把**颗数 + 总价**都塞在行尾：

```
旧：补到够升墨刃      差 7.995e+16 颗 · 1.998e+18 金币
```

3 位小数让行尾多了 4 个字符，左侧标签直接被省略号截掉（`补到够…`）—— 玩家会看不懂这行是干什么的。改成行尾只留「花多少金币」，颗数与单价挪进悬停注释：

```
新：补到够升墨刃      花 1.998e+18 金币
    悬停 → 还差 7.995e+16 颗墨晶（单价 25 金币），一次补齐到能再升一级墨刃。
```
