# 键灵 v0.14.1 · 「领取每日礼包时卡死」：改动 + 取证

> 反馈的原话是「领取每日礼包时卡死闪退」。这一版没能复现出同样的现象，所以做了两件事：
> 把点击里唯一可能有风险的那一步改掉，再让程序以后能自己记下现场。

---

## 一、现场是什么样的

翻了 `key spirit.log`，最后一行是：

```
16:20:56 每日礼包（5,000 档）：金币 +95.4T · 墨晶 +40
```

也就是说**领取本身是成功的**——钱已到账、日志已写。之后：

- 没有下一行「已存档」（存档是每 30 秒一次，本该在 15 秒后出现）；
- 没有「未处理异常」；
- Windows 事件日志、`%LocalAppData%\CrashDumps` 里没有任何一次键灵的崩溃记录。

结论：进程是在**没抛异常、也没走退出流程**的情况下没的。这种死法只有两种来源——界面线程卡住后被人为结束，或者 CLR 之外的原生层直接终止。两种都不会留下任何痕迹。

## 二、本地怎么试的（都没复现）

| 试法 | 目的 | 结果 |
|---|---|---|
| 真实鼠标注入：光标移到这一行、按下、抬起（不是模拟事件） | 走完整的鼠标捕获与命中测试 | 领取成功，界面再活 20 秒正常 |
| 高压连点 150 次（每点一次都重建子列） | 撞偶发的时序问题 | 界面心跳一次没断 |
| 从托盘位置展开面板（贴屏幕底边，子列可用高度被压到最小） | 换一套布局数值 | 正常 |
| 气泡停留 20 秒后再点 | 注释窗口在场时销毁行 | 正常 |

四种全部正常。这条路径本身没有稳定可复现的问题，说明它要么与环境有关，要么是"运气型"的时序问题。

## 三、改了什么

### 1. 点击不再在输入事件里拆控件树

子列里几乎每个动作（买墨晶、开墨匣、领礼包、强化、切页）都是「改状态 + 立刻重建子列」。旧写法是在 `MouseLeftButtonUp` 里直接重建——等于**在事件还沿着控件树派发的时候，把正在派发这条事件的控件连同它的子元素一起销毁**。

WPF 多数时候扛得住，但这条路本身是靠运气：一旦输入路由或布局在事后回头读那个已失效的元素，界面就会卡住。而领取礼包的动作恰好是「钱到账、日志写过之后」才重建子列，卡在这里的表现就是——钱收到了，游戏没了。

现在动作统一排到 `DispatcherPriority.Input` 之后执行：事件已经走完全程，拆谁都不会再有人在用。玩家侧感知不到延迟（不到一帧）。

### 2. 动作抛异常时，日志里写明是哪一行

以前行内动作抛异常会冒到全局，只知道「有异常」不知道「点了什么」。现在会写：

```
点击「5,000 档」抛异常：……
```

### 3. 现场取证：`diag.log`

新增 `%LocalAppData%\KeySpirit\diag.log`，平时不存在，只在三种情况下写：

| 情况 | 写入内容 |
|---|---|
| 界面线程连续 10 秒没心跳 | `⚠ 界面无响应约 12s，最后动作：执行「5,000 档」` |
| 界面线程恢复 | `界面已恢复（卡了约 12s，最后动作：…）` |
| 非 UI 线程抛出未处理异常 | 完整异常（以前这种异常会直接杀掉进程，一个字都不留） |

看门狗用**独立的日志文件和独立的锁**，不走 `Log.Write`——因为卡死的典型情形就是界面线程正卡在写日志的锁上，看门狗再去抢同一把锁等于把唯一的取证机会也一起卡掉。

另外，程序正常退出时会写一行 `程序退出（正常路径）`。以后日志末尾没有这一行，就说明进程是被结束或直接没的，不用再靠猜。

## 四、如果还出现

把这两个文件的最后几十行发我即可定位：

```
%LocalAppData%\KeySpirit\diag.log
%LocalAppData%\KeySpirit\key spirit.log
```
