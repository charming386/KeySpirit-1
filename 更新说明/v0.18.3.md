# v0.18.3 —— 三位小数只留在详情页，主列血条恢复一位

> 起因：「你误会了，我的意思是只有角色详情页变成三位小数，一级菜单里的那个血条旁边的数值依然是 1 位小数，否则血条太短了」

## 一、v0.18.2 把位数做成了全局常量，这是个错误

上一版把 `Fmt.SciDigits` 定成 `3` 并写死进 `Sci()`，于是**所有**走大数格式化的地方都变成了三位——包括主列血条旁边那行：

```
主列（232 宽，v0.18.2）  生命 9.940e+15 / 9.940e+15  ← 比原来长 4 个字符
主列（232 宽，现在）     生命 9.9e+15 / 9.9e+15
```

主列本来就紧：那一行是「文字 + 血条」左右并排，文字宽一点，血条就被压短一点。三位小数把血条挤掉了一截，而这恰恰是玩家最常盯的一根条。

**位数不是全局属性，是按场景选的属性。** 上一版把「详情页要精度」当成了「所有地方都要精度」。

## 二、改法：`digits` 变成调用参数，默认 1

```csharp
public const int DetailDigits = 3;                       // 只有详情页显式传

static string Sci(double mantissa, int exp, int digits)

public static string Large(Big v, int digits = 1)        // 默认 1：主列 / 托盘 / 日志
public static string Small(Big v, int digits = 1)        // 同上
```

哪一档用几位，现在一目了然：

| 位置 | 位数 | 理由 |
|---|---|---|
| **主列血条旁**（`生命 X / Y`） | **1** | 232 宽，还得跟血条分地方；血条长度比第三位小数重要 |
| 主列金币 / 墨晶 | 1 | 同上 |
| 托盘悬停提示 | 1 | 只有 176 宽，三位必截断 |
| 日志 | 1 | 日志是流水，读的是量级 |
| **角色详情**（等级 / 生命 / 攻击 / 防御 / 墨根） | **3** | 306 宽放得下；这一页就是「看数值」的地方 |
| **战斗详情**（怪物与我方攻防） | **3** | 同上，方便对照「还差多少打不动它」 |
| **本命器属性预览**（`生命 X → Y`） | **3** | 连点升级看涨幅，正是当初要三位的原因 |

K/M/B/T 段（`842.7K`、`278.2T`）**两种口径都保持 1 位**——那是带单位的短写法，不是科学记数法；跟着变只会撑宽，而且 4 位有效数字已经够看出 6% 的涨幅。

## 三、顺带确认：商店那行不用再缩短了

v0.18.2 因为三位小数把「补到够升墨刃」行尾挤爆，改成只留金币。现在行尾回到 1 位，`花 2.0e+18 金币` 比原来短，那处改动**保留**——行尾只留一个金额本来就比「颗数 + 总价」干净，颗数与单价在悬停注释里。

## 四、自测

175 项全过（原 172）。新增 7 条，其中第一条就是**防回归**的：

```csharp
Check("主列口径默认 1 位（血条旁的数字不能变长）",
    Fmt.Large(new Big(9.945, 15)) == "9.9e+15", ...);
```

谁再把默认值改成 3，这条会立刻红。其余六条锁定：详情页 3 位、补足 `.000`、1e+500 档同样 3 位、0.1% 差别在详情页能分开而主列分不开、K/M/B 段两种口径都是 1 位、`Small` 也跟随位数。

- 文档：`CHANGELOG.md`、`README.md`、本文件、设计稿 10.1 / 10.2。

**不需要存档迁移**，Schema 仍 3：只改显示，且只改详情页那几行。
