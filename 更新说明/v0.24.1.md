# v0.24.1 —— 商店「补到够升墨刃」补上「金币不足」

> 起因：「补够的这个没显示金币不足」（截图里买墨晶、开墨匣两行红字写着「金币不足」，中间这一行却白字写着「花 52.5B 金币」）

## 一、它一直没看金币

这一行从建出来那天起，判断「能不能点」只看一件事：**墨晶还差多少**。

```csharp
Add(RowMake("补到够升墨刃", $"花 {…} 金币", () => FillToNext(0),
    enabled: shortfall > 0));      // ← 只看墨晶缺口，Gold 一次都没出现
```

于是出现截图那一幕：金币和所需金额差着好几个数量级，它照样白字挂着「花 52.5B 金币」，鼠标移上去还是小手（cursor 是 Hand），点下去**什么都不发生**——`FillToNext` 里 `AffordCount(InkPrice) < 1` 就静默 `return`。三行并排，上下两行都说「金币不足」，中间那行不说。

第二个毛病是**它建行时就把文案定死了**：没有 `Tick`，金币每秒在涨、墨晶被别处花掉，这一行的字和可点状态都不会变。

## 二、改成和上下两行同一套

行恒可点，状态每秒重判，三种结果：

| 状态 | 左侧 | 右侧 | 字色 |
|---|---|---|---|
| 墨晶已够升一级 | 补到够升墨刃 | 已够 | 灰 |
| 差墨晶、金币够 | 补到够升墨刃 | 花 X 金币 | 白 |
| 差墨晶、金币不够 | 补到够升墨刃 | **金币不足** | 灰 + 红字 |

悬停注释也跟着状态走：金币不够时除了「还差 N 颗」，还会明说「现在金币不够，点下去只会按买得起的部分补 M 颗」——因为 `FillToNext` 本来就是能补多少补多少，不是全有或全无。

## 三、顺手修的颜色复位问题

买墨晶、开墨匣两行原先是在 `Tick` 里直接改 `Label.Foreground` 和 `Hint.Foreground`。听着没问题，但**鼠标一移上去就会失效**：`MouseEnter` 会调 `Paint(row)`，而 `Paint` 把字色还原成建行时捕获的默认色——「金币不足」的红字你越把鼠标挪过去看，它越白。

现在颜色改由 `Row.Muted`（灰字）和 `Row.HintWarn`（红字）两个状态位表达，`Paint` 是唯一上色的地方，悬停、移出、每秒刷新三方能吵的架没了。

## 四、自测

191 → **193 项**，新增两条锁住底层行为（界面状态没法在自测里画，就把「点了到底动没动」钉死）：

- 金币为 0 时点「补到够升墨刃」：金币、墨晶一个都不动（缺口 2 颗 / 需 50 金币 · 金币 0）
- 金币给够后点同一行：缺口补平到能再升一级墨刃（金币 975 · 余缺口 0）

全过。

## 五、影响范围

只动 `UI/PanelWindow.cs` 的商店段与行着色：`Row` 加两个状态位、`Paint` 据此裁决、`RowMake` 的注释气泡改成读 `row.Note`（这样注释才能随状态换）。游戏数值、存档、界面结构一律没动。
