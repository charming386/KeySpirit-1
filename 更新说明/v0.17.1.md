# 键灵 v0.17.1 · 「今日敲击」分母修成 20,000，金币袋袋数改由敲击数算

> 问题原话是：「今日敲击不应该是 4800/20000 吗？而且就算达到了上限，也应该是去掉后面的 /20000，只显示当前敲击数，并持续计数，只不过不再算金币袋（所以下面的也是错误的，是基于敲击数而不是领取次数的）」

这是 v0.15.0 定「500 敲一袋、每日 40 袋」时留下的两处显示口径问题，数值一点没动。

## 一、`4,800 / 5,000` 为什么是错的

「今日敲击」右侧那串原本跟的是**「下一档还没到的门槛」**：4,800 敲时下一档是 5,000，所以显示 `4,800 / 5,000`。问题是这一页下面明摆着还有一行「20,000 档」，于是同一屏里出现了两个上限：分母说今天能敲 5,000，第二档却说 20,000。

```
旧：分母 = 下一个未达标档位的门槛      → 4,800 / 5,000（到 5,000 后跳成 5,000 / 20,000）
新：分母 = 今日上限 20,000（40 袋 × 500 敲）→ 4,800 / 20,000（一直不变）
```

## 二、到顶之后：分母消失，数字继续涨

20,000 敲是今天的掉袋名额上限（40 袋），到了就不再掉袋——但**敲击本身当然还在记**。这时候再留一个 `/ 20,000` 只会显示成 `21,360 / 20,000` 这种倒挂，所以到顶后分母直接去掉：

| 状态 | 显示 |
|---|---|
| 未到顶、没有可领的档 | `4,800 / 20,000` |
| 未到顶、有档可领 | `6,000 / 20,000 · 可领 1 档` |
| 已到顶、有档可领 | `21,360 · 可领 2 档` |
| 已到顶、全领完 | `21,360` |

「· 可领 N 档」留着是有意的：那是「这里能点」的提示，不是进度分母，到顶之后照样有用。要是你觉得到顶后连它也多余，说一声就去掉。

「统计 › 今日敲击」用的是同一段文案（`DailyKeysText`），两处口径从此不会再分家。

## 三、顺手把一处容易看错的地方写明白

每日礼包**一天就两个**：5,000 档 1 次、20,000 档 1 次。它不是「每 5,000 敲领一次」的重复奖励——档位由 `DailyTiers` 写死，`DailyMask` 按位记住今天领过哪档，领过就灰掉，敲到 5 万也不会冒出新的档。

但只看两行 `5,000 档` / `20,000 档`，很容易反过来理解成「按 5,000 一档往上加」。所以这一版把标题改成 **「每日礼包（2 档 · 各 1 次）」**，两行的悬停注释也补了一句「每天只有这一次，领过就灰掉，敲得再多也不会再出现」。自测里加了两条断言把它钉住：档位恒为 2 个、5,000 档领过后敲到 50,000 依然不可领、提示也只说剩下那 1 档。

## 四、`今日 0/40 袋` 与 `4,800 敲` 自相矛盾

第二张图里「金币袋：暂无·每 500 敲一袋（今日 0/40 袋）」配着「今日敲击 4,800」，看着像坏了。原因不是算错，而是**两个数来自两个源**：

- 今日敲击读 `DailyKeys`（落盘）；
- 袋数读 `DailyBags`（v0.15.0 才加的计数器，老存档里是 0）。

旧档升级上来、或者当日中途换过版本，`DailyKeys` 已经有值而 `DailyBags` 还是 0，两个数就分家了。

掉袋本来就是「每 500 敲一袋」的确定节奏，袋数天然等于 `今日敲击 ÷ 500`，所以这次**直接把袋数改成派生值**，不再读那个计数器：

```
旧：袋数 = 另存的计数器 DailyBags（可能与敲击数分家）
新：袋数 = min(今日敲击 / 500, 40)      → 4,800 敲 = 今日 9/40 袋
```

顺带把三件跟着计数器走的旧账一起结掉：

| 旧问题 | 原因 | 现在 |
|---|---|---|
| 重开一次白扔最多 499 敲的零头 | 累加器 `bagCounter` 只在内存里，不落盘 | 判据是「今日敲击 % 500 == 0」，零头跟着 `DailyKeys` 一起落盘 |
| 转生时要手动清零 `bagCounter` | 担心「带着旧层的敲击进度」 | 不需要了：袋值本来就按掉落那一刻的层数现算 |
| 老存档 `DailyBags=0` 与敲击数矛盾 | 两个源 | 派生，不可能再对不上 |
