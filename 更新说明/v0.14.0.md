# 键灵 v0.14.0 · 存档迁移：等级按曲线反算

> 上一版 v0.13.0 换了升级需求公式，却没管旧档里已经攒下的等级。这一版补上：读档时按「到达过的最高层」反算应得等级，多出来的收走。

---

## 一、为什么会有这个改动

升级需求公式换过两次。每一次都只会让「同样一只怪给的经验，相对一级所需的量」变少，但**已经攒到等级里的那部分不会被倒扣回去**。结果就是：

| | 旧档 | 同层数的新档 |
|---|---|---|
| 到达层数 | 386 层 | 386 层 |
| 等级 | 1,247 | 940 |
| 等级乘区 | ×19.7 | ×15.1 |

同一层数、同一身强化，旧档凭空多出 30% 攻击、40% 生命。这不是设计上的奖励，是公式换代留下的缝隙。

## 二、怎么算「应得等级」

一层给的经验当量 = 8 只小怪 + 1 只精英 + 1 只守层者 = `8 + 精英倍率 + 守层倍率`；一级要 `k = 2 + 0.58×√层` 只当量，所以这一层能升 `当量 ÷ k` 级。从第 1 层逐层累加即可，不用逐只怪模拟。

| 到达过的最高层 | 应得等级 | 等级乘区 |
|---|---|---|
| 100 | 296 | ×5.4 |
| 237 | 619 | ×10.3 |
| 386 | 940 | ×15.1 |
| 500 | 1,175 | ×18.6 |
| 1,000 | 2,152 | ×33.3 |
| 3,000 | 5,742 | ×87.1 |
| 9,999 | 17,433 | ×262 |

**自己算一遍**：`等级 ÷ √层` 在低层偏高（第 1 层就白送几级），几百层之后稳定在 `1.5 × 层`——每打穿一层必升 1.5 级，这就是当前曲线的节奏。

## 三、三条边界（写死在实现里）

- **只收不放**。等级高于曲线的收回曲线；**低于曲线的保持原样**——那是玩家自己的进度，不该被垫高。你现在如果低于 940 级，进游戏后等级不会变。
- **只迁一次**。存档里加了结构版本号 `Schema`，迁移跑完打上标记，此后不再干预。挂机反复刷层本来就该多拿等级，不能变成常驻天花板。
- **经验同步压**。等级收下来后，本级经验可能已经够升好几级，一并压到本级 90% 以内；否则下一次结算立刻又顶回原等级，等于没迁。

## 四、你可能会看到的

- 如果等级原本高于曲线：**等级数字变小、属性面板掉一截**。这是预期行为，不是掉档。
- 如果等级原本低于曲线：什么都没发生，只是存了一次档（下次启动不会再走迁移）。
- 迁移动作会写一行日志：`存档迁移：等级 1247 → 939（按第 386 层反算，旧曲线多出的部分已收走）`。

## 五、附带修正的文案

设计稿 4.1 原来写「等级 ≈ 43 × √层」，那是 v0.13.0 提高精英/守层者经验倍率**之前**的口径。现在每层必升约 1.5 级，等级是随层数**线性**涨的（9,999 层 17,433 级，不是 4,300 级），文档已改正；同段的「9,999 层约 17,700 级 / ×267」也按实测收成 17,400 / ×262。

## 验证

自测 124 → **129 项**，全过。新增覆盖：

- 应得等级随层数递增，且 386 层 ≈ 940、9,999 层 ≈ 17,433；
- 旧档 1,247 级按 386 层收回曲线，且经验不会立刻顶回上一级；
- 迁移只做一次（打过 `Schema` 标记后不再压等级）；
- 低于曲线的档保持原样，不会被垫高；
- 初始化重置后的存档带上了 `Schema` 标记（否则重置后在第 1 层刷到高等级，一重启会被当成旧档压回 5 级——这是本版开发过程中自查出的、只在重置路径上才犯的错）。
